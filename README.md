# Safety-Certified Aggregation (SCA)

**Anytime-valid, region-stratified certificates for gating federated aggregation — and a set of
negative results about the search procedure that was supposed to make them tight.**

> [!IMPORTANT]
> **The empirical results of every previous version of this repository are WITHDRAWN.**
> They were produced by a harness with 100% train/test leakage, an acceptance gate that read the
> ground-truth labels of the set it was scoring, a rejection path that was a no-op, and an
> "attack" that raised accuracy. None of those numbers is reproduced here and none of them should
> be cited. See [§12, What changed and why](#12-what-changed-and-why--the-retraction).
>
> This document reports a **rebuilt** library measured on real
> [PKU-SafeRLHF](https://huggingface.co/datasets/PKU-Alignment/PKU-SafeRLHF) data at 10 seeds.
> Every quantitative result below is regenerated by a committed script and carries a key into
> [`results/headline_numbers.json`](results/headline_numbers.json); the few setup and provenance
> figures that come from anywhere else are individually flagged where they appear. Two of the
> three hypotheses did not come out as hoped, and both appear in the abstract rather than a
> footnote.

## Abstract

We study the problem of *behaviourally* gating federated aggregation: at each round the server
holds a candidate global model, tests it on data the clients never see, and commits the round only
if the test certifies that the model's violation rate is below a target ε with probability ≥ 1−δ.
The natural way to spend a test budget is adaptively — search for failures, then measure hardest
where failures were found — but that is exactly what invalidates a Hoeffding-style certificate.

We contribute one positive result and three that cut against the design they were meant to support.

**(1) A corrected, anytime-valid certificate (H1: SUPPORTED).** We separate *search* from
*estimation*: an adaptive mutation/graph search allocates the budget, and a disjoint pool supplies
fresh i.i.d. draws that alone feed the bound. Theorem 1 union-bounds over the a-priori grid of
(region, sample-count) pairs, which makes the per-region width valid *simultaneously for every*
`m ∈ [1, M]` and therefore valid at a data-dependent `m_j`. Monte-Carlo coverage under an
optimal-stopping adversary is **0.99995** (1 failure in 20,000 trials) against a target of 0.9.
The test has power: the pre-rebuild fixed-`m` width covers **0.8601** and the pre-rebuild
data-derived-`K` rule covers **0.0000**, both correctly failing.

**(2) Search-guided allocation does not tighten the bound (H2: NOT SUPPORTED).** At matched budget,
search-guided allocation gives a certified bound of **0.2823** [0.2409, 0.3248] versus **0.2815**
[0.2397, 0.3245] for the closed-form `w^(2/3)` rule — i.e. it is *looser*, by +0.00077 at p = 0.3359.
This is analytically expected: `w^(2/3)` is the exact minimiser of the quantity the certificate
reports, and since `p̂_j` is unbiased at any `m_j`, moving budget toward suspicious regions can only
degrade the width term. The honest claim is that adaptive allocation is now **sound**, not that it
is **beneficial**.

**(3) A mutator that does nothing beats the real mutation operators (the pre-rebuild "7–10×
recursive amplification" headline is refuted).** At exactly matched budget, an **IDENTITY** mutator
that returns an unmodified copy scores raw amplification **8.87×**, and a **NULL** mutator that
appends whitespace scores **8.68×**, against the real operators' **7.28×**. Raw amplification
rewards re-querying the same failure, which a no-op maximises. Deduplicated to distinct depth-0
ancestors the amplification is 1.00 by construction; the quotable discovery number is **22.4**
[15.5, 29.9] distinct failing inputs, never a multiplier.

**(4) The gate helps under attack, but the strongest-looking evidence is the weakest (H3:
partially supported).** With the harness fixed so that clean FedAvg (0 attackers) *beats* the
frozen checkpoint — **0.6302** [0.5936, 0.6654] vs **0.5782** [0.5723, 0.5840], the criterion whose
failure made the old Byzantine headline meaningless — the gate improves held-out accuracy in 20 of
25 aggregator × attack configurations. But of the five configurations reaching p < 0.05, the four
positive ones all include seeds where the gate rejected every round (so the "gain" is partly the
do-nothing baseline), and the only significant result in the stratum where the gate was *never*
inert is a **harm** (median under ALIE, −0.0442, p = 0.0156). Under a Bonferroni correction over
the 25 configurations, exactly one survives, and it is one where the gate was inert on 7/10 seeds.

Stripped of vocabulary, the method is **adaptive stratified sampling with anytime-valid
per-stratum bounds, used to gate federated aggregation**. That is a modest, real, useful thing.
It is not a state-of-the-art robustness result, and this README does not claim one.

## 0. A note on the repository name

The repository is named *"…via Recursive **Language Model** Verification…"* and the verifier class
is still `RLMVerifier`. **There is no language model in the loop.** The "model" under test is a
100,516-parameter bag-of-words logistic classifier over GPT-2 token ids, deployed as a release
filter; the mutation operators are template rewrites, not LM paraphrases; the safety predicate is a
lookup over human safety annotations, not an LM judge. Optional LM-backed mutators exist in
`sca/verifier/mutations.py` but are **not** used for any number in this document.

Accurate names for what is implemented:

| Component | Honest name | Legacy name in code |
|---|---|---|
| The method | Safety-Certified Aggregation (SCA) | unchanged |
| The bound | anytime-valid region-stratified Hoeffding UCB | "Hoeffding-UCB acceptance rule" |
| The search | recursive **mutation** search + graph-guided frontier probing | `RLMVerifier` ("Recursive Language Model") |
| The graph | proximity graph over embedding-space region centroids | Model Knowledge Graph (MKG) |

The repository name is kept only so existing links do not break. Read it as a historical artifact.

## 2. What the method actually is

### 2.1 Setting

`n` clients hold private data; at round `t` the server aggregates candidate parameters
`θ̃ = A(θ_t; Δ_1, …, Δ_n)` with an aggregation rule `A` (FedAvg, coordinate-wise median, trimmed
mean, Krum, FLTrust). Up to `f` clients are Byzantine. Parameter-space defences inspect gradient
geometry; they cannot see what the model *outputs*. SCA adds a behavioural admission test on
server-held data.

The deployed object is a **release filter**: given `(prompt, candidate response)` the model either
releases the response verbatim or emits a fixed refusal string. A **violation** is "an unsafe
response reached the user", judged by a predicate `φ(x, y)` on the *released text*. This is
deliberately not classification error — wrongly refusing a safe response costs utility but is not a
violation — and the predicate never sees the label of the input it is scoring. That distinction is
the structural fix for audit finding F2, in which the old gate computed
`is_violation = (pred != true_label)` on the very set it was certifying.

### 2.2 The three-stage protocol

The old design used the *same* adaptively-generated samples both to search for failures and to
estimate the violation rate. Hoeffding does not survive that. The rebuild separates them:

```
Stage A — SEARCH / ALLOCATION      (search pool; search_* counters)
    recursive mutation expansion + graph-guided frontier probing
    output: a per-region suspicion score.  Touches the bound: NEVER.

Stage B — ESTIMATION               (disjoint estimation pool; estimation_* counters)
    allocate m_j across the K regions using the Stage-A scores (data-dependent: now LEGAL)
    draw m_j fresh i.i.d. samples from D|R_j, record to estimation_*

Stage C — CERTIFICATE
    bound = Σ_j w_j · UCB_j, computed from estimation_stats ONLY
```

The separation is enforced in the data structures, not by convention:
`sca/knowledge_graph/regions.py` gives every region two disjoint counter pairs
(`record_estimation_sample` / `record_search_sample`), and there is no code path by which a mutant
reaches an estimation counter. `sca/experiments/data.py` guarantees the pools are disjoint at the
level of row ids *and* prompt groups, and `assert_disjoint()` raises if any id appears twice.

Region weights `w_j = |stratum_j| / |pool|` are computed from the estimation pool alone and frozen
before verification begins.

### 2.3 Theorem 1 (anytime-valid stratified upper bound under adaptive allocation)

**Hypotheses — all four are required, and none may be relaxed silently.**

* **(H-a)** A measurable partition of the input space into `K` regions `R_1 … R_K`, a per-region
  budget cap `M ≥ 1`, and `δ ∈ (0,1)`, **all declared before any data is observed**. `K` and `M`
  may never be derived from the data.
* **(H-b)** For each region, the estimation samples are **i.i.d. draws from `D | R_j`**, and are
  *not* selected by the search. No independence *across* regions is needed — the union bound does
  not require it.
* **(H-c)** Weights `w_j ≥ 0` with `Σ_j w_j = 1`, fixed before verification, such that `D`
  decomposes as `Pr_D[violation] = Σ_j w_j p_j`.
* **(H-d)** The realised sample counts `m_j ∈ {0,…,M}` are arbitrary and may be chosen with full
  knowledge of every draw.

**Statement.** For each region `j` let `X_{j,1}, X_{j,2}, …` be i.i.d. Bernoulli(`p_j`) with
`p_j = Pr_{x ~ D|R_j}[x is a violation]`, and let `p̂_j^(m)` be the mean of the first `m`. Define

```
W(m) = sqrt( ln(2·K·M/δ) / (2m) ),      W(0) = +∞
UCB_j = min(1, p̂_j^(m_j) + W(m_j))       (so UCB_j = 1 when m_j = 0)
```

Then

```
Pr[ ∀j :  p_j ≤ UCB_j ]  ≥  1 − δ,
```

and on that same event `Σ_j w_j p_j ≤ Σ_j w_j UCB_j`.

**Proof.**

*Step 1 (fixed pair).* Fix `j ∈ [K]` and `m ∈ [M]`. The variables `X_{j,1},…,X_{j,m}` are i.i.d. in
`[0,1]`, so Hoeffding gives `Pr[p_j − p̂_j^(m) ≥ t] ≤ exp(−2mt²)` for `t > 0`. Taking `t = W(m)`
makes `2mt² = ln(2KM/δ)`, hence

```
Pr[ p_j − p̂_j^(m) ≥ W(m) ]  ≤  δ / (2KM).
```

The factor 2 inside the logarithm is not needed for this one-sided statement; `ln(KM/δ)` would
suffice. It is kept deliberately so that the *same* constant also controls the lower deviation and
can therefore be used two-sidedly for diagnostics and for the regression subgraph without a caller
ever mixing constants. The price is a factor `sqrt(ln(2KM/δ)/ln(KM/δ))`, typically under 1.05.

*Step 2 (union bound over an a-priori index set).* Let `B_{j,m} = {p_j − p̂_j^(m) ≥ W(m)}`. There
are exactly `K·M` such events and — this is the crux — the index set `[K] × [M]` is fixed *before*
any data is seen, because `K` and `M` are declared a priori by (H-a). By the union bound,
`Pr[⋃_{j,m} B_{j,m}] ≤ K·M·δ/(2KM) = δ/2 ≤ δ`. Let `E` be the complement, so `Pr[E] ≥ 1 − δ/2`.

*Step 3 (transfer to data-dependent sample sizes).* The event `E` is quantified over *all*
`m ∈ [M]` simultaneously; its definition never mentions `m_j`. Therefore, deterministically, on
every sample path `ω ∈ E` and every `j`,

```
p_j < p̂_j^(m)(ω) + W(m)   for every m ∈ [M],
```

and in particular for `m = m_j(ω)` whenever `m_j(ω) ≥ 1`. **No optional-stopping or measurability
argument is required**: an adversary choosing `m_j` cannot land on a pair `(j, m)` that is not
already covered, because every pair is covered. If `m_j(ω) = 0` then `UCB_j = 1 ≥ p_j` trivially,
and clipping at 1 is harmless since `p_j ≤ 1`.

*Step 4 (weighted aggregate).* On `E`, multiplying `p_j ≤ UCB_j` by `w_j ≥ 0` and summing gives
`Σ_j w_j p_j ≤ Σ_j w_j UCB_j`, and the left side is exactly `Pr_D[violation]` by (H-c). ∎

**Cost.** Relative to a fixed-`m` bound the anytime version pays `sqrt( ln(2KM/δ) / ln(2K/δ) )` — a
`sqrt(ln M)` inflation. That factor is the entire price of making adaptive, search-guided allocation
legal.

The proof lives in the module docstring of [`sca/utils/stats.py`](sca/utils/stats.py) so it cannot
drift away from the code, and is Monte-Carlo verified by
[`sca/experiments/run_soundness.py`](sca/experiments/run_soundness.py) and `tests/test_stats.py`.

### 2.4 What the certificate does **not** cover

Read this before quoting any bound.

1. **It certifies the estimation pool, not the world.** Region samples are drawn i.i.d. *with
   replacement from the estimation stratum*, so `p_j` is the model's violation rate on the
   empirical distribution of an 800-row server pool. Generalising from that pool to PKU-SafeRLHF,
   let alone to deployment, is a second inferential step this repository does **not** perform. The
   defensible sentence is "at most ε on the held-out verification pool". The sentence "at most ε on
   PKU-SafeRLHF" is **not** licensed, and neither is any statement about safety in the world.
2. **It says nothing about a rejected model.** There is no completeness or power guarantee. A
   rejection means the evidence was insufficient to certify, not that the model is unsafe.
3. **It is a single-certificate statement.** Running the gate for `T` rounds and reporting the best
   bound requires a further union bound over `T`; `δ` must be divided by `T` by the caller. The
   experiments here report per-round certificates and do **not** apply that correction, so the
   round-level acceptance decisions in the FL arm are not jointly `(1−δ)`-valid across rounds.
4. **It inherits the predicate.** `φ` is a lookup keyed strictly on the response text against human
   safety annotations. It is only as good as those annotations, and it raises rather than guessing
   on an unseen response. There is no "return safe when the judge is unavailable" path anywhere in
   the module — that failure mode turns an outage into a clean bill of health.
5. **It is not a statement about the classifier's accuracy** and must not be read as one: a refusal
   is safe by definition, so a model that refuses everything is trivially certifiable and useless.
   Utility is measured separately, on a held-out test set the gate never sees.
6. **Hypothesis (H-b) is an assumption about the code, enforced by the code.** If a mutant ever
   reaches an estimation counter, Theorem 1 is void. That is why the counters are physically
   separate and why the search/estimation pools are asserted disjoint.

### 2.5 The gate in the federated loop

```
clients → Δ_i → A(·) → candidate θ̃ → Stages A/B/C on the server pool
                                          ├── accept → commit θ_{t+1} = θ̃
                                          └── reject → roll back to θ_t
```

Rejection is a real state change: `sca/federated/server.py` records `rollback_was_noop` per round,
and the two mandated controls (`always_reject` ≡ frozen checkpoint, `always_accept` ≡ ungated run)
are asserted **inside the run** at the level of parameter bytes; a failure raises and aborts the
sweep. In the previous version, aggregation wrote into a `deepcopy` that rollback then "restored",
so rejection changed nothing — which is how the old Byzantine headline was really the frozen
checkpoint doing nothing (finding F5).

All values below are the committed configuration, serialised verbatim into
`results/headline_numbers.json → provenance.config`. The one exception is the split sizes, which

| Model | bag-of-words logistic head over GPT-2 token ids, **100,516 parameters** (`model_parameter_count`) |

| Verifier budget | search 400, estimation 1,600, max depth 3, branching 3, 2-hop neighbourhoods, hashed embedder |

| Adversary | 2 of 8 clients Byzantine |
| Aggregators | fedavg, median, trimmed_mean, krum, fltrust |
| Attacks | sign_flip, ipm, alie, targeted_safety, legacy_gaussian (the last is the pre-rebuild zero-mean-noise control, kept on purpose) |
| Seeds | 42, 123, 456, 789, 1024, 2048, 4096, 8192, 16384, 32768 |

† split sizes from `results/data_split_report.json`; everything else from
`results/headline_numbers.json → provenance.config`.

**Why ε and the budget must be chosen together.** The following is arithmetic from the a-priori
constants, not a measurement. At `K = 8, M = 300, δ = 0.05` the width is `sqrt(ln(96000)/(2 m_j))`.
A total estimation budget of 600 would give `m_j ≈ 75` and a width of ≈ 0.276 *before a single
violation is observed*, so no model however safe could clear ε ≈ 0.3 and the gate would reject
everything for budget reasons alone. `B = 1600` (`m_j ≈ 200`) is chosen so the certificate can
discriminate. This is a real design constraint of the method, not a tuning knob, and it is
documented in the config dataclass along with the measured bounds at both budgets.

## 6. Results — the certificate (H1)

Source: [`results/soundness_theorem1.json`](results/soundness_theorem1.json), regenerated by
`python -m sca.experiments.run_soundness`. Configuration `K = 12, M = 4000, δ = 0.10`, 20,000
trials, true weighted violation rate 0.5, target coverage 1 − δ = 0.9.

| Quantity | Coverage | Verdict | Claim key |
|---|---|---|---|
| Optimal-stopping adversary (sees the whole sample path, picks the `m` minimising the UCB) | **0.99995** (1/20,000 failed) | passes | `H1_coverage_optimal_stopping_adversary` |
| Pilot-then-reallocate adversary (moves the budget to the lowest observed-rate half) | **0.99995** (1/20,000 failed) | passes | `H1_coverage_adaptive_reallocation_adversary` |
| Weighted aggregate `Σ_j w_j p_j ≤ Σ_j w_j UCB_j` | **1.00000** (0/20,000 failed) | passes | `H1_coverage_weighted_aggregate` |
| **Negative control**: pre-rebuild fixed-`m` width, same data, same adversary | **0.8601** | correctly **fails** | `H1_negative_control_legacy_fixed_m_coverage` |
| **Negative control**: derive `K` from the data after dropping empty regions (finding F10) | **0.0000** | correctly **fails** | `H1_negative_control_data_derived_k_coverage` |

**Verdict: H1 SUPPORTED** (`H1_verdict`). 20,000 trials is 10× the mandated minimum, the adversary
is the strongest available (optimal stopping upper-bounds what any real allocator can do to break
the bound), and the experiment demonstrably has the power to detect an invalid bound, because both
negative controls fail.

Coverage far exceeds nominal, which means the bound is **conservative, not tight**. That is the
expected behaviour of a union bound over `K·M` pairs, and it is the reason H2 has so little room to
move.

### 6.1 The honest nuance H1 must carry

At the parameters the experiments actually use — `K = 8, M = 300, δ = 0.05` — the *negative control
does not fail*: it covers 0.9599 against a target of 0.95
(`H1_at_experiment_parameters_negative_control_correctly_fails = False`, and the coverage value
itself is in [`results/soundness_theorem1_at_experiment_params.json`](results/soundness_theorem1_at_experiment_params.json)),
while Theorem 1 covers 0.9999 (`H1_at_experiment_parameters_coverage`). The anytime correction is demonstrably necessary at
`M = 4000`; at `M = 300` this Monte-Carlo experiment simply has **no power to demonstrate its
necessity**. The theorem requires the correction regardless — `ln M` does not stop existing at
`M = 300` — but do not present the `K = 8` run as the soundness evidence. The discriminating run is
`soundness_theorem1.json`.

### 7.1 Certified bounds (lower is tighter)

### 7.2 H2 — does search-guided allocation tighten the bound? **NOT SUPPORTED**

| comparison | difference (ours − baseline) | ours tighter? | p | min attainable p |
|---|---|---|---|---|
| vs `w23_allocation` | **+0.00077** | **no** | 0.3359 | 0.0020 |
| vs `proportional_allocation` | **+0.00063** | **no** | 0.3047 | 0.0020 |
| vs `uniform_allocation` | −0.00304 | yes | 0.0605 | 0.0020 |

Keys `H2_search_guided_vs_w23`, `H2_search_guided_vs_proportional`, `H2_search_guided_vs_uniform`,
`H2_verdict`. The minimum attainable two-sided p at 10 seeds is 0.0020, so **the test is not
underpowered by construction** — the effect genuinely is not there. Note that even the one
favourable comparison, against uniform, does not clear 0.05.

**Why this is analytically expected rather than bad luck.** Minimising `Σ_j w_j sqrt(c / (2 m_j))`
subject to `Σ_j m_j = B` has the exact Lagrangian solution `m_j ∝ w_j^(2/3)`. So `w^(2/3)` is the
*optimum of the quantity the certificate reports*, and no data-dependent reallocation can beat it:
`p̂_j` is unbiased at any `m_j`, so shifting budget toward regions the search found suspicious can
only degrade the width term, which is the only term the allocator controls. Search guidance buys
nothing for a Hoeffding-style bound. (This also corrects finding F14: the old `optimal_allocation`
used `m_j ∝ w_j`, which is not the minimiser of anything the code reports.)

**This was a real test, not a no-op.** The allocations genuinely differ — on seed 42, uniform gave
`{229,229,229,229,228,228,228,0}`, `w^(2/3)` gave `{290,143,235,212,274,169,277,0}`, and
search-guided gave `{300,180,280,124,300,116,300,0}` (per-run allocations are in
`verifier_arm.json → rows[*].allocation`). In the pre-rebuild code, by contrast, the "MKG-guided"
and "blind" arms were bit-identical at matched budget because τ = 1.0 made every region adjacent to
every other (finding F4), so the comparison could not have come out any other way.

**What survives.** The positive claim is H1, not H2: the contribution is that adaptive allocation is
now *legal*, and the measured cost of legality is a `sqrt(ln M)` widening. If you only ever intend
to allocate by a closed-form rule, you do not need Theorem 1 — a fixed-`m` bound suffices and is
tighter.

### 7.3 The mutator controls, and why the old amplification headline is refuted

At exactly matched budget (all six arms declare search budget 400 and estimation budget 1,600, and
the realised query counts are equal across all 60 runs — check `verifier_arm.json → rows[*]`,
`search_queries` / `estimation_queries` / `distinct_sources`; this was verified, not assumed):

* **IDENTITY** mutator (returns an unmodified copy): raw amplification **8.87×**, raw violations
  142.4 [135.5, 149.9].
* **NULL** mutator (appends whitespace): **8.68×**, raw violations 138.7 [131.6, 146.5].
* **Real operators** (paraphrase / escalation / template / tool-pivot): **7.28×**, raw violations
  121.7 [108.5, 134.3].

`F8_null_mutator_raw_beats_real_operators = True` and
`F8_identity_mutator_raw_beats_real_operators = True`. The raw-violation CIs of the identity arm and
the real-operator arm do **not** overlap. No paired significance test for that specific comparison
is recorded in the claim map, so read it as a CI separation, not as a p-value.

**The mechanism.** An identity mutant produces the same released text and therefore the same
verdict, so every recursion level re-counts the same failure. A real rewrite sometimes flips the
model's decision and *lowers* the count. "Amplification" as previously defined literally rewards
doing nothing. The operators are not degenerate — search-guided genuinely rewrites the prompt
(`"Use the search tool to find: <prompt>"`, `"Call the API to: <prompt>"`,
`"I need you to <prompt>"`), null appends whitespace, identity is a no-op — they simply lose on this
metric.

**The quotable number is the deduplicated one.** `F8_deduplicated_amplification = 1.00` **by
construction**: once violations are deduplicated to distinct depth-0 ancestors each failing input is
counted exactly once, so there is no multiplier left to report. Quote **22.4 [15.5, 29.9] distinct
failing inputs**, never an "N× amplification".

**A structural caveat that must travel with this result** (`F8_mutator_control_caveat`). The
deduplicated counts are byte-identical across all six arms including identity. That is *forced by
the search design, not measured*: Phase 2 of `sca/verifier/rlm_verifier.py` builds its expansion
queue as

```python
[i for i, t in enumerate(traces) if t.violation and t.depth < max_depth]
```

i.e. it expands only **already-violating** traces, so a mutation can never turn a non-violating
depth-0 seed into a violating one, and the deduplicated count is fully determined by the flat
Phase-1 seeds. Identical deduplicated counts across arms are therefore **not** evidence about the
operators. Only the raw comparison discriminates, and on the raw comparison the no-op wins.

A separate reporting defect worth knowing about: the column labelled "ampl. DEDUP 0.14×" in
`results/README_NUMBERS.md` is `distinct_violations / distinct_sources` — a *discovery rate* of
0.14, not an amplification — while its caption calls it "the only one that may be quoted". It is
correctly re-labelled in the claim map as
`discovery_violation_rate_over_distinct_sources__<arm>`. Do not quote that figure file's caption.

### 7.4 The region graph (F4) and the regression subgraph (F11)

Mean edge density **0.2452** (`F4_mkg_edge_density`). A density of 1.0 is the complete graph, which
is what the pre-rebuild hardcoded `τ = 1.0` produced in all five experiment scripts — making
"MKG-guided" and "blind" exploration set-identical. τ is now auto-calibrated to a target-density
quantile of the pairwise centroid distances, and `check_density` raises `DegenerateGraphError` when
the realised density leaves its band, so a degenerate graph fails loudly instead of silently
producing a constant-factor "improvement".

The regression subgraph now ranks regions by the change in the **point estimate** `p̂`, not by the
change in the UCB. Ranking by UCB difference (what the old code did) is dominated by the difference
of Hoeffding widths: a region the baseline sampled ≤ 3 times has `ucb_old = 1.0`, forcing
`Δ_j ≤ 0`, so three regions that went from a 0.000 to a 1.000 violation rate were invisible to that
rule (finding F11). Regions with too little evidence on either side are now reported as
"insufficient evidence" rather than scoring ≤ 0.

expected behaviour of a conservative admission test, and a useful diagnostic rather than an

## 10. Limitations

These are consistent with the abstract, not a retraction of it.

### 10.1 What the certificate covers is narrow

Theorem 1 certifies the violation rate on the **empirical distribution of the 800-row server
estimation pool**, sampled with replacement, with `m_j` reaching ≈ 200 per region. It is not a
statement about PKU-SafeRLHF as a population, and emphatically not about safety in deployment. Nor
is it valid across rounds without dividing `δ` by the number of rounds, which the FL experiments do
not do. See [§2.4](#24-what-the-certificate-does-not-cover) for the full list.

### 10.2 The bound is conservative and search does not help it

Measured coverage of 0.99995 against a target of 0.9 means most of the interval is union-bound
slack. Combined with H2, the practical advice this repository supports is: *use the closed-form
`w^(2/3)` allocation*. The value of Theorem 1 is that it makes a data-dependent allocation legal for
anyone who wants one for other reasons (e.g. reusing the search output for triage), not that it
makes the certificate tighter.

### 10.3 The FL harness was changed to make C1 pass, and a reviewer should scrutinise that

To satisfy C1, `n_rounds` went 8 → 20, `lr` 0.5 → 5.0, `local_epochs` 1 → 5. What was **not**
changed: Dirichlet α (0.5), pretraining strength (5 epochs, lr 0.1, momentum 0.9), corpus size,
model, or anything in the verifier arm. In particular the server pretraining pool was **not**
weakened, because weakening a baseline to make a criterion pass is the exact failure mode this
rebuild exists to undo — the frozen checkpoint remains the strongest thing the server can build from
its own data.

The justification that this is a harness fix rather than tuning is a measured learning curve. It is
recorded in the `ExperimentConfig` docstring of `sca/experiments/run_all.py` — a committed
diagnostic sweep, **not** a `results/` artifact, so it carries no claim key and is quoted here only
as the reason for the change: centralised training on the 4,800-row client union reaches 0.6637
held-out while the 800-row server pool reaches 0.5381, so the client data carries ≈ +0.13 that
FedAvg was failing to extract, while FedAvg on those same rows reached only ≈ 0.572. The diagnosis
is an **optimisation** gap, not a data ceiling: `build_clients` does not pass momentum through to
`local_sgd` (which supports it), so clients run plain SGD while the pretraining reference runs
momentum 0.9 — an effective learning rate roughly 10× larger. The equivalent plain-SGD knob is the
learning rate, which is what C1 authorises adjusting. The selection criterion was fixed before
looking (maximise the number of seeds where FedAvg beats frozen, subject to not collapsing to a
constant predictor) and no hypothesis was consulted.

Two honest consequences. **(a)** The root cause is still unfixed: passing momentum into
`build_clients` would likely give C1 on 10/10 with a lower, less brittle learning rate, and the 10×
learning-rate proxy is why one clean seed still collapses. **(b)** A 5-seed sweep picked a different
configuration that did not survive re-measurement on all ten seeds (6/10, mean −0.0061, four
collapses), which is a good reminder that the 10-seed numbers are the only ones quoted here.

### 10.4 The mutator controls are decisive only on the raw metric

Because Phase 2 expands only already-violating traces, the deduplicated counts are identical across
arms **by construction** (§7.3). The real-operators-versus-identity comparison is therefore a
single-metric result. A search that could promote a non-violating seed to violating — e.g. expanding
a neighbourhood around near-misses — would make the deduplicated comparison informative, and is the
obvious next experiment.

### 10.5 Scale

8,000 rows, 8 clients, 20 rounds, and a 100,516-parameter bag-of-words logistic head. Absolute
accuracies sit between roughly 0.47 and 0.72 against class priors of ≈ 0.52/0.48, so several arms
are close to the prior and it is the collapse detector, not the accuracy, that distinguishes them.

### 10.6 The FL sweep is not itself replicated

C4 verifies byte-identical reproduction of the verifier arm at production config and of the smoke
pipeline across three processes. The 590-configuration FL sweep ran once (3h45m) and was not re-run
for a byte-comparison, on time grounds.

## 11. Threats to validity

**Construct validity — the model is not a language model.** Every claim about "safety verification"
here concerns a release filter built from a bag-of-words classifier. Mutation operators that rewrite
a prompt template can change that classifier's decision, but they are not adversarial prompts and
the classifier is not an LM. Nothing in these results licenses a claim about safety-gating LLM
outputs. The repository name is misleading on this point; see §0.

**Construct validity — the predicate.** `φ` is a lookup against human annotations keyed on response
text. It is output-sensitive (checked by `assert_output_sensitive`) and it raises on unseen
responses, but it is not an independent safety judgement: it inherits every bias and error of the
PKU-SafeRLHF annotation.

**Internal validity — the harness change.** §10.3. If you believe lr = 5.0 is unreasonable, re-run
with `--lr` and `--n-rounds` and re-measure; the numbers will move, and the H3 conclusion depends on
C1 continuing to hold.

**Internal validity — multiplicity.** 25 H3 configurations, 3 H2 comparisons and 5 attack tests are
reported without correction. §8.2 states what survives Bonferroni (one configuration) and what does
not (everything in the never-inert stratum).

**Statistical validity — paired permutation tests at 10 seeds.** The minimum attainable two-sided
p is 2/2¹⁰ ≈ 0.0020. That is small enough to be usable — unlike the pre-rebuild 5-seed tests, whose
minimum attainable p was 0.0625 while their own criterion was p < 0.05, i.e. unreachable
(finding F14) — but p-values quantise coarsely near the threshold.

**External validity — the benchmark suites in this repo are synthetic.**
`sca/experiments/benchmarks.py` contains `SafetyBenchSuite`, `JailbreakBenchSuite`,
`TruthfulQASuite` and `ToxiGenSuite` whose generators emit strings like
`f"Safety question {i} about privacy"` while their docstrings cite real venues and real dataset
sizes (finding F12). **No number in this document comes from those suites.** They should be deleted
or renamed; they are not evidence of anything, and their presence must not be read as benchmark
coverage.

**What a reviewer should distrust most, in order.** (1) The C1 harness change. (2) Any reading of H3
that quotes 20/25 without the stratification. (3) Generalising the certified bound beyond the
800-row estimation pool. (4) The relevance of a bag-of-words release filter to LM safety.

## 12. What changed and why — the retraction

The previous version of this README graded 6 of 7 claims "Proven" while its own Limitations section
conceded that the mechanisms behind three of them were inert. A five-lens audit, with every finding
confirmed by execution against that code, found the following. Numbers in this section are quoted
from the withdrawn version and from the audit that refuted it; **none is a measurement of the
rebuilt code**.

| # | Defect in the withdrawn version | What was done |
|---|---|---|
| F1 | 100% train/test leakage — the test set was drawn from the client training indices; 400/400 test points were client training points, so every published accuracy was training accuracy | `sca/experiments/data.py` builds disjoint client / search / estimation / test splits with `assert_disjoint()`; overlaps are printed per seed (C2) |
| F2 | The gate computed `is_violation = (pred != true_label)` on the set it was scoring and never called the `safety_predicate` it was handed — the "certified" quantity was identically the empirical error rate | The model is deployed as a release filter and `φ` judges the released text; `assert_output_sensitive` checks the predicate depends on the output; the private gate reimplementation is deleted |
| F3 | Theorem 1 was false as implemented: the recursion recursed only on violating nodes and every mutant fed the same counter that became `p̂_j`. A shipped-config counterexample certified 0.3849 ≤ ε while the true rate was 0.90 | Physically separate search and estimation counters; the bound sees `estimation_stats` only |
| F4 | The knowledge graph was the complete graph — τ = 1.0 hardcoded in all five scripts, 780 edges = C(40,2). "MKG-guided" and "blind" were bit-identical at matched budget | τ auto-calibrated; realised density 0.2452; `DegenerateGraphError` on a degenerate graph |
| F5 | Rejection was a strict no-op (aggregation wrote into a `deepcopy`), so "93.75% under 50% Byzantine" was the frozen checkpoint. Meanwhile clean FedAvg with zero attackers finished at 0.84, so "reject everything" was accuracy-maximising by construction | Real accept/rollback with per-round `rollback_was_noop` instrumentation; `always_reject ≡ frozen` and `always_accept ≡ no gate` asserted in-run; C1 now holds, so rejecting costs 0.052 |
| F6 | The "attack" was zero-mean Gaussian noise independent of the model; two attackers had cosine −0.007; it *raised* FedAvg accuracy from 0.84 to 0.9225 | Four coordinated attacks (sign_flip, ipm, alie, targeted_safety) plus the Gaussian kept as a labelled control; all five now degrade undefended FedAvg (§8.3) |
| F7 | Clients were label-sorted contiguous chunks, so each was single-class; Krum picked one and became a constant predictor whose 0.47 class prior was reported as accuracy | Dirichlet(0.5) non-IID splits; a collapse detector flags any run predicting one class on > 97% of the test set; zero-adversary controls for every aggregator (§8.4) |
| F8 | "7–10× recursive amplification" was re-counting; a whitespace mutator scored 10.5× against the real operators' 9.5×, and deduplicated the amplification was 1.00× | Raw **and** deduplicated counts reported for every arm; NULL and IDENTITY mutator arms are mandatory controls; the identity mutator wins (§7.3) |
| F9 | Results did not reproduce — `embedding.py` used builtin `hash()` and `PYTHONHASHSEED` was set nowhere; three processes with seed 42 gave three different embeddings | `sca/utils/seeding.stable_hash` (blake2b) replaces every string `hash()`; `make repro-check` runs three processes with hash randomisation active (C4) |
| F10 | `check_acceptance([], ε, δ)` returned `(True, 0.0)` — zero evidence certified exactly zero — and `K` was derived from the data after dropping empty regions, so the most degenerate run got the smallest union-bound penalty | `k_total` and `budget_cap` are a-priori arguments; unsampled regions contribute UCB = 1 and are never dropped; empty input is vacuous with bound 1.0. Reproduced as an MC negative control that covers 0.0000 |
| F11 | The regression subgraph ranked by Δ of the UCB, which is dominated by width differences, so three regions that went 0.000 → 1.000 could not be flagged | Ranking by Δ`p̂`; "insufficient evidence" reported explicitly |
| F12 | Fabricated benchmark suites — synthetic generators with docstrings citing real venues and real dataset sizes | Still present and still fabricated; **no result here uses them**. Flagged in §11 for deletion |
| F13 | Tests covered 0% of every module producing a paper number; replacing all nine (5,008 lines) with `raise RuntimeError` still gave 105 passed | The suite now exercises the library that produces the numbers, with a measured coverage floor enforced by `make coverage` |
| F14 | `optimal_allocation` used `m_j ∝ w_j` (the Lagrangian gives `w_j^(2/3)`); the significance test's minimum attainable p was 0.0625 at 5 seeds while its own criterion was p < 0.05; Merkle proofs were broken for non-power-of-two trees; the README claimed 3.3M parameters for a 6,466,690-parameter model | `w^(2/3)` implemented and shown to be the optimum (§7.2); 10 seeds gives min attainable p = 0.0020; the parameter count is now counted programmatically (100,516) and written into the results file |

its concessions 170 lines below its "Proven" verdicts, where they could not affect a reader's

## 13. Related work

Every citation below was checked against its published record while writing this document.

**Validation-gated aggregation — the closest prior work.** *FLTrust* (Cao, Fang, Liu, Gong, NDSS
2021, [arXiv:2012.13995](https://arxiv.org/abs/2012.13995)) is the direct ancestor of this design:
the server holds a small clean *root dataset*, trains a server model on it, and scores each client
update by its cosine similarity to the server update. *Zeno* (Xie, Koyejo, Gupta, ICML 2019,
[arXiv:1805.10032](https://arxiv.org/abs/1805.10032)) ranks candidate updates by a suspicion score
computed from the loss decrease they produce on server-held data, tolerating any number of faulty
workers provided one is honest. Both use server data to validate updates; both score in *parameter
or loss* space, and neither attaches a finite-sample certificate to the decision. The only thing SCA
adds is that the admission test is a *stratified statistical estimate with an explicit (ε, δ)
guarantee* on a behavioural quantity. FLTrust is also included here as a baseline aggregator, where
it is net-harmful with zero adversaries (§8.4).

**Robust aggregation.** *Krum* (Blanchard, El Mhamdi, Guerraoui, Stainer, NIPS 2017) selects the
update minimising the sum of distances to its nearest neighbours. Coordinate-wise *median* and
*trimmed mean* with optimal statistical rates are due to Yin, Chen, Ramchandran and Bartlett (ICML
2018, [arXiv:1803.01498](https://arxiv.org/abs/1803.01498)). All operate on gradient geometry and
are behaviourally blind, which is the gap this work probes — though §8.4 shows they also carry a
real cost when there is nothing to defend against.

**Attacks.** *ALIE* (Baruch, Baruch, Goldberg, NeurIPS 2019,
[arXiv:1902.06156](https://arxiv.org/abs/1902.06156)) shows that small, well-crafted perturbations
inside the benign variance envelope evade all of the above. *Inner Product Manipulation* (Xie,
Koyejo, Gupta, UAI 2019, [arXiv:1903.03936](https://arxiv.org/abs/1903.03936)) breaks median and
Krum by negating the inner product with the honest direction. Both are implemented in
`sca/experiments/attacks.py` and both degrade undefended FedAvg here (§8.3).

**Anytime-valid inference — what the corrected theorem draws on.** The correction that makes
adaptive allocation legal is a crude, finite-horizon instance of a much better-developed literature:
time-uniform confidence sequences (Howard, Ramdas, McAuliffe, Sekhon, *Time-uniform, nonparametric,
nonasymptotic confidence sequences*, Annals of Statistics 49(2), 2021,
[arXiv:1810.08240](https://arxiv.org/abs/1810.08240)) and betting-based confidence sequences for
bounded means (Waudby-Smith and Ramdas, *Estimating means of bounded random variables by betting*,
JRSS-B 86(1):1–27, 2024, [arXiv:2010.09686](https://arxiv.org/abs/2010.09686)). This repository uses
a union bound over a finite a-priori grid of `(region, m)` pairs, which is simpler and strictly
weaker than a supermartingale confidence sequence; a betting-based sequence would be tighter and
would remove the need for an a-priori cap `M`. That is the single most promising improvement to the
statistics here. Framing the acceptance decision as risk control also connects to *Learn then Test*
(Angelopoulos, Bates, Candès, Jordan, Lei,
[arXiv:2110.01052](https://arxiv.org/abs/2110.01052)), which calibrates a predictor to satisfy a
finite-sample risk guarantee by reframing the problem as multiple hypothesis testing.

**Stratified allocation.** The `w^(2/3)` rule — the exact minimiser of the width-weighted
objective, and the tightest point estimate in §7.1 — is the Hoeffding analogue of classical
*Neyman allocation* for
variance (Neyman, *On the two different aspects of the representative method*, JRSS 97(4):558–625,
1934), which allocates `m_j ∝ w_j σ_j`. The two rules differ because the objectives differ: a
Hoeffding width does not depend on the within-stratum variance.

**Adaptive search for failures.** The Stage-A design is a mutation-based search with a
coverage-style frontier, in the tradition of coverage-guided greybox fuzzing (Böhme, Pham,
Roychoudhury, *Coverage-based Greybox Fuzzing as Markov Chain*, CCS 2016), and of automated red
teaming for language models (Perez, Huang, Song, Cai, Ring, Aslanides, Glaese, McAleese, Irving,
*Red Teaming Language Models with Language Models*, EMNLP 2022,
[arXiv:2202.03286](https://arxiv.org/abs/2202.03286)). The negative result in §7.3 — that an
identity mutator beats the real operators on the discovery metric — is a caution about that
literature's *evaluation practice*, not a claim about those systems: **any** discovery metric that
counts violating *traces* rather than distinct violating *inputs* rewards re-querying a known
failure.

**Data.** PKU-SafeRLHF and BeaverTails (Ji, Liu, Dai, Pan, Zhang, Bian, Chen, Sun, Wang, Yang,
*BeaverTails: Towards Improved Safety Alignment of LLM via a Human-Preference Dataset*, NeurIPS 2023
Datasets and Benchmarks Track, [arXiv:2307.04657](https://arxiv.org/abs/2307.04657)). Human safety
meta-labels are used verbatim; nothing is inferred from response text.

## 15. Citing this repository

If you use this code, cite it as a **software artifact with a corrected soundness proof and a set of
negative results**, not as a benchmark result. Do not cite any number from a commit before the
rebuild. If you take one thing from it, take the experimental design rather than the numbers:

* separate search from estimation, in the data structures and not by convention;
* declare `K`, `M`, `ε` and `δ` before you look at the data, and let unsampled regions cost you 1;
* run a no-op control for every discovery mechanism you claim credit for;
* assert that "always reject" equals "do nothing" and that "always accept" equals "no gate", inside
  the run;
* check that your attack is an attack, and that your defence has something to defend against.

Every one of those five would have caught at least one of the defects that made the previous version
fiction.
